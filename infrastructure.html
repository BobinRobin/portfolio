Инфраструктура

Один сервер несёт на себе всё: оркестрация, очереди, базы, CI/CD, интеграционные сервисы и наблюдаемость. Серверная платформа построена «с нуля» и развивалась как ответ на конкретные боли.

Эволюция платформы

Подготовка сервераДисковая подсистема (RAID), установка Linux, настройка сети и доступа.
Контейнерная платформаKubernetes (K3s), nginx как edge, Redis как транспорт событий, PostgreSQL.
Первые боевые сервисыДва интеграционных сервиса с ручным деплоем bash-скриптами.
CI/CDGitLab CI/CD: сначала императивный деплой из пайплайна.
НаблюдаемостьPrometheus + Grafana + Loki: метрики, логи, SRE-дашборды.
GitOps и безопасностьArgoCD (декларативный деплой), Vault (секреты), Terraform/Ansible, секреты вне Git.
Масштабирование контроляrequests/limits, непривилегированные контейнеры, PDB, NetworkPolicy.

Ключевые решения

GitOps

CI собирает, ArgoCD деплоит

CI собирает образ и обновляет image.tag в values.yaml; ArgoCD применяет. Откат — это git revert. Правда всегда в Git, кластер — производное от Git.

CI/CD

Стадии test/build/gitops

Тесты (uv + pytest), многоступенчатая сборка образа (кэш по слоям), push в registry и обновление тега. Отдельный слой для зависимостей — кэш Docker работает лучше.

Security

Секреты не в Git

Креденшилы вынесены из кода и CI в Kubernetes Secret и Vault по принципу least privilege: сервис получает доступ ровно к своему секрету. Контейнеры работают от непривилегированного пользователя, ресурсы заданы явно.

Observability

RED-метрики и метки логов

Rate / Errors / Duration для каждого сервиса, бизнес-каунтеры статусов, Promtail с меткой unit по systemd. Дашборд отвечает на вопрос «сколько готово, что падает, что ждёт».
