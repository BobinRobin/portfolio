Playbook и примеры

Готовые фрагменты для обучения и портфолио: runbook, Terraform, Ansible, CI/CD. Паролей и реальных адресов нет — только структура и подходы, как это делают в production.

Runbook: разбор инцидента

# Incident response — общий порядок
1. Зафиксировать симптом: что именно сломалось, с какого времени, кто заметил.
2. Оценить влияние: какой контур затронут, есть ли данные/статусы под риском.
3. Проверить гипотезы сверху вниз по стеку:
   - nginx/ingress (маршрут, 5xx)
   - сервис (статус pod/unit, логи, restarts)
   - очередь (Redis: длина stream, обработка)
   - база (подключение, схемы, блокировки)
4. Найти первопричину, а не симптом: «что изменилось перед сбоем».
5. Исправить минимально, с бэкапом/ревертом.
6. Проверить результат по данным (статус записи, callback), а не по «вроде заработало».
7. Записать postmortem: что, почему, как не допустить повторно.

Terraform: namespace и лимиты

# main.tf — декларативное описание namespace (упрощено)
terraform {
  required_providers {
    kubernetes = { source = "hashicorp/kubernetes" }
  }
}

resource "kubernetes_namespace" "app" {
  metadata { name = var.namespace }
}

resource "kubernetes_limit_range" "app_limits" {
  metadata { namespace = kubernetes_namespace.app.metadata[0].name, name = "app-limits" }
  spec {
    limit {
      type = "Container"
      default = {
        cpu    = "500m"
        memory = "512Mi"
      }
      default_request = {
        cpu    = "250m"
        memory = "256Mi"
      }
    }
  }
}

Ansible: установка агента логов

# playbook.yml — настройка Promtail на хосте (упрощено)
- hosts: app
  become: true
  vars:
    loki_url: "http://127.0.0.1:3100/loki/api/v1/push"
  tasks:
    - name: Установить Promtail
      apt:
        name: promtail
        state: present

    - name: Прописать конфиг journald с меткой unit
      template:
        src: promtail.yml.j2
        dest: /etc/promtail/config.yml
      notify: restart promtail

    - name: Включить и запустить
      systemd:
        name: promtail
        enabled: true
        state: started

  handlers:
    - name: restart promtail
      systemd:
        name: promtail
        state: restarted

GitLab CI: test / build / gitops

# .gitlab-ci.yml — CI собирает образ и двигает тег, ArgoCD применяет
stages: [test, build, gitops]

variables:
  IMAGE_TAG: "$CI_COMMIT_SHORT_SHA"
  HELM_VALUES: "deploy/helm/app/values.yaml"

test:
  stage: test
  script:
    - pip install uv
    - uv sync --frozen --group dev
    - uv run pytest -q

build:
  stage: build
  script:
    - docker login -u "$CI_REGISTRY_USER" -p "$CI_REGISTRY_PASSWORD" "$CI_REGISTRY"
    - docker build -t "$CI_REGISTRY_IMAGE:$IMAGE_TAG" .
    - docker push "$CI_REGISTRY_IMAGE:$IMAGE_TAG"

gitops:
  stage: gitops
  only: [main]
  script:
    - sed -i "s|^  tag: .*|  tag: \"$IMAGE_TAG\"|" "$HELM_VALUES"
    - git commit -m "ci: deploy $IMAGE_TAG" || true
    - git push origin HEAD:main
Все креденшилы заменены переменными CI/CD и плейсхолдерами. Реальные пароли/токены в репозитории и на сайте не хранятся.
