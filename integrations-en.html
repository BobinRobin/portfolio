Enterprise integrations

End-to-end data-exchange loops with external systems. The priority is reliability: idempotency, reconciliation, error handling, observability.

Marking

State marking system

Orders, stickers, imports, SSCC. Strict XML contracts, chunking up to the per-document limit, FTP exchange, callback to HQ, prod/test schemas.

E-invoicing

Incoming documents

Pipeline: logs-only intake → Redis stream → worker → DB. Idempotency on input, a gate before writes, dry-run: external channels enabled one at a time.

Batch ETL

Sales / inventory

Scheduled Python ETL (CronJob). GitLab CI, multi-stage Dockerfile, Helm, ArgoCD.

Reliability patterns

PatternWhy
Idempotency from day oneRetries are safe; the key must be truly unique
Dry-run before go-liveRun without external channels first, then enable one by one
Gate before writesOnly validated data reaches the database
Contract-driven chunkingRespect external limits, preserve ordering
Reconciliation & tracingStatus at the data level, end-to-end code path
ObservabilityIncidents are visible in metrics and logs
Contract details and counterparty names are generalized.
