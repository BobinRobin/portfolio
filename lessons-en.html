Lessons & anti-patterns

The things I have already stepped on. Kept here so I do not hit the same rake twice.

Idempotency

The key must be unique

Re-processing must not duplicate records. Idempotency from day one, with a truly unique key.

Integrations

Do not guess file names

We searched for a response file by one field while the external system named it by another. The file name and schema of an external system are law.

Deployment

Enable channels one at a time

Never enable FTP/callback/sales at once. Run in dry-run first, then enable channels one by one.

Observability

Metrics before the incident

Without RED metrics and logs you fix blind. Minimum: rate/errors/duration and a "what fails, what queues" dashboard.

Tooling

One layer, one tool

Do not add a second tool for the same job. Dual runtime (systemd + Kubernetes) is tech debt to converge.

Network

Proxies break "it can't see"

"Grafana can't see Loki" was a proxy conflict. Check network mode and datasource address first.

Security

Secrets never in Git

Move credentials to Secret/Vault with least privilege; run containers as non-root.

GitOps

Rollback is git revert

Imperative deploys left drift between Git and the cluster. GitOps: the truth is in Git.

How I use this

Before a new service I run a checklist: idempotency on input, dry-run of external channels, requests/limits, non-root container, RED metrics, secrets out of Git. It covers most past failures.
