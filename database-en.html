Data Layer, Vector Search & Event Queues

Strict role separation: distributed TBase for high-volume business data, local PostgreSQL 16 for CI/CD tooling, Qdrant for RAG knowledge retrieval, and two isolated Redis instances (event streams + distributed locks).

Distributed SQL · Business

TBase (PostgreSQL 10 · Sharded)

Distributed Greenplum-like RDBMS (max_connections=2500) storing marking registries, UPDs, sales marts, and price monitoring. Tables are sharded by provenance key (e.g. DISTRIBUTE BY SHARD(file_md5)) so DELETE + INSERT runs inside a single shard without cross-node locks.

Vector DB · AIOps RAG

Qdrant (infra-knowledge · 779 vectors)

Stores 1024-dim BAAI/bge-m3 Cosine embeddings with on-disk payload. Indexes architecture docs, postmortems, runbooks, and skills across all 6 contours, returning top-k context in milliseconds on alert triggers.

Streams & Distributed Locks

Two Isolated Redis 7 Instances

Primary Redis powers asynchronous event streams (utd:uploads, utd:ingest) with AOF+RDB persistence. Dedicated lock-redis (:6378) handles cross-process TTL locks (SET NX EX + Lua release) for concurrent RPA sessions.

Tooling & Object Storage

PostgreSQL 16 + MinIO (S3)

Local PostgreSQL 16 is isolated for GitLab and CI/CD. Two MinIO instances store S3 artifacts, backups, and MLflow model weights.
