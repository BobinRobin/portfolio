Уроки и анти-паттерны

На чём я уже наступал. Записал, чтобы не повторять одни и те же грабли.

Идемпотентность

Ключ должен быть уникальным

Звучит банально, пока на ретрае не получаешь дубли. Теперь: проверяю ключ до вставки. Всегда.

Интеграции

Не гадай имена файлов

Искал файл ответа по EAN, а система называла его по номеру строки. Полдня потеряно. Имя файла и структура внешней системы — закон.

Деплой

Каналы — по одному

Включил разом FTP, callback и sales? Добро пожаловать в заварушку. Теперь dry-run сначала, потом по одному.

Наблюдаемость

Метрики — до инцидента

Чинил вслепую, пока не запилил RED-метрики. Теперь «что падает и что ждёт» видно сразу.

Инструменты

Один слой — один инструмент

Два инструмента на одну задачу — два места, где всё ломается. Двойной рантайм (systemd + K8s) — техдолг, сводим к одному.

Сеть

Прокси виноват чаще, чем код

Grafana не видела Loki. Начал чинить не то. Оказалось — прокси. Проверяй сеть и конфиг первыми.

Безопасность

Секреты не в Git

Креденшилы в коде и CI — критический риск. Теперь Vault + least privilege, контейнеры не от root.

GitOps

Откат — это git revert

kubectl patch из CI оставлял расхождение между Git и кластером. Теперь правда в Git, откат — revert.

Как этим пользуюсь

Перед запуском нового сервиса прогоняю чек-лист: идемпотентность на входе, dry-run внешних каналов, requests/limits, непривилегированный контейнер, RED-метрики, секреты вне Git. Он закрывает большую часть прошлых граблей.
