Слой данных, векторный поиск и очереди

Чёткое разделение ролей: распределённая СУБД TBase для высокообъёмных бизнес-данных, локальный PostgreSQL 16 для CI/CD, векторная БД Qdrant для RAG-знаний и два изолированных контура Redis (стримы событий + межпроцессные замки).

Distributed SQL · Business

TBase (PostgreSQL 10 · Sharded)

Распределённая Greenplum-подобная СУБД (max_connections=2500). Хранит реестры кодов маркировки, УПД, витрины продаж и прайс-мониторинга. Таблицы шардируются по ключу идемпотентности (например, DISTRIBUTE BY SHARD(file_md5)), чтобы DELETE + INSERT выполнялся строго внутри одного шарда без кросс-узловых блокировок.

Vector DB · AIOps RAG

Qdrant (infra-knowledge · 779 векторов)

Хранилище векторных эмбеддингов BAAI/bge-m3 (1024d, Cosine, on-disk payload). Индексирует архитектуру, постмортемы, runbook-и и скиллы всех 6 контуров; отдаёт релевантный контекст за миллисекунды при срабатывании алертов.

Streams & Distributed Locks

Два изолированных инстанса Redis 7

Основной Redis обслуживает асинхронные стримы (utd:uploads, utd:ingest, аудит) с персистентностью AOF+RDB. Выделенный lock-redis (:6378) отвечает за межпроцессные распределённые блокировки (SET NX EX + Lua release) для RPA-сессий.

Tooling & Object Storage

PostgreSQL 16 + MinIO (S3)

Локальный PostgreSQL 16 изолирован под нужды GitLab и CI/CD. Два инстанса MinIO хранят S3-артефакты, дампы и веса моделей MLflow.
