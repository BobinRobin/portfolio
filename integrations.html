Enterprise-интеграции

Сквозные контуры обмена данными с внешними государственными и корпоративными системами. Главное в них — не «связать», а сделать надёжно: идемпотентность, сверка, обработка ошибок, наблюдаемость.

Integration · Production

Маркировка «Честный знак»

Сквозной контур маркировки: заказы, стикеры, импорт, SSCC.

  • XML-контракты внешней системы: имя файла и структура — закон
  • Чанкинг: >29999 кодов на документ, порядок сохраняется
  • FTP-обмен, чтение результата по точному имени файла
  • Callback в HQ, мультиокружение (прод/тест схемы)
Integration · Systemd

Приём УПД (документооборот)

Конвейер приёма и обработки УПД от корпоративного HQ.

  • Приём «logs-only» → Redis stream → worker → БД
  • Идемпотентность на входе: повторный пост не дублирует запись
  • Gate перед записью в БД: не сохраняем то, что не прошло стадию
  • Dry-run: внешние каналы включаются по одному, не разом
Batch ETL · GitOps

Sellout / inventory (эталонный проект)

Разовый batch-ETL на Python, запускается по расписанию (CronJob).

  • GitLab CI: test / build / gitops, uv + pytest
  • Dockerfile: многоступенчатый, непривилегированный пользователь
  • Helm-чарт: CronJob, requests/limits явно
  • ArgoCD применяет, откат = git revert

Паттерны надёжности, которые я применяю

ПаттернЗачем
Идемпотентность с первого дняРетраи и повторные посты безопасны; ключ должен быть действительно уникальным
Dry-run перед боемСначала конвейер без внешних каналов, затем включение по одному — ошибки ловятся до отправки во внешнюю систему
Gate перед записьюВ БД попадает только то, что прошло нужную стадию обработки
Чанкинг по контрактуБольшие документы дробятся по лимиту внешней системы с сохранением порядка
Сверка и трейсыСтатусы на уровне данных, сквозная трассировка кода от входа до результата
НаблюдаемостьRED-метрики и логи с метками — инцидент виден, а не ищется вручную
Имена внешних систем и детали контрактов обобщены для публичного портфолио.
