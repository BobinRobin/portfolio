Инциденты

Реальные сбои из боевого контура. По каждому: симптом, причина, исправление, что изменилось.

Sticker: новые коды не уходили на FTP

Симптом. Новые записи писались в базу, но XML на FTP не отправлялся. В логе — skip_no_pd=1000.

Причина. Дата продукта бралась только из существующих строк; новые коды вставлялись без неё, хотя даты лежали в отдельной таблице.

Решение. Дописал batch-процессор: для кодов без даты ищем её в дополнительном источнике и пишем обратно. Заодно исправил подсчёт признака «есть работа».

Результат. Коды снова уходят на FTP; расхождение «данные есть — отправки нет» устранено.

Идемпотентность: неверный ключ дублировал записи

Симптом. Повторная обработка создавала дубли: ключ идемпотентности не был уникален для документа.

Решение. Перевёл дедупликацию на действительно уникальный ключ и проверил сценарий повторного поста.

Результат. Повторный ввод перестал дублировать записи; ретраи стали безопасными.

Grafana не видела Loki

Симптом. После сборки стека наблюдаемости Grafana не доставала логи из Loki.

Причина. Конфликт прокси на сервере.

Решение. Перевёл Grafana на host network, datasource через loopback. Сборщик логов перевёл на journald с меткой systemd-юнита.

Результат. Логи доступны в Grafana и фильтруются по конкретному воркеру.

Блокеры запуска контура (критические дефекты)

Симптом. При доведении контура до боевого запуска аудит исходников выявил дефекты, блокировавшие rollout.

Решение. Исправил: асинхронную логику в FTP-опросе (гонки, потеря результата), несогласованный контракт callback, обход лимита чанкинга, отключённую идемпотентность, открытые секреты (вынес в секрет-хранилище).

Результат. Контур доведён до безопасного состояния; внешние каналы включаются по одному.

Наблюдаемость с нуля

Симптом. Метрик не было, логи воркеров читали вручную.

Решение. Собрал Prometheus + Grafana + Loki: RED-метрики, бизнес-каунтеры статусов, два SRE-дашборда.

Результат. Диагностика перестала быть «вслепую»: инцидент виден по метрикам и логам.

Выводы

  • Идемпотентность — с первого дня, ключ должен быть уникальным.
  • Внешние каналы включать по одному, а не разом.
  • Наблюдаемость — до инцидента, а не после.
