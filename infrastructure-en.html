Infrastructure

The platform that runs two integration services. Built from scratch and matured to GitOps.

Architecture

How it evolved

Bare-metal setupRAID, Linux, network and access.
PlatformK3s, nginx, Redis (queues), PostgreSQL.
First servicesManual deployment via bash scripts.
CI/CDGitLab CI: tests, build, deploy.
ObservabilityPrometheus, Grafana, Loki. RED metrics.
GitOpsCI builds and moves the tag in Git, ArgoCD applies. Rollback = git revert.
SecurityVault, secrets out of Git, non-root containers, requests/limits.

Why this path

Each step fixed a concrete pain of the previous one, not "because it is trendy":

  • K3s over full K8s — one node: a lighter control plane for the same API and Helm/ArgoCD ecosystem.
  • GitOps over kubectl patch — CI-only deploys left drift between Git and the cluster; ArgoCD reconciles to Git, rollback is revert.
  • Redis as a stream — a buffer between intake and processing; workers restart independently.
  • Vault / Secret over secrets in code — least privilege, rotation, audit.
  • RED metrics over raw CPU/RAM — a dashboard that answers "what is failing and what is queued".
Topology and addresses are intentionally not disclosed.
